DESIGN-001 Wireframe: MSSP Portal Changes

Limited-scope changes to the MSSP Partner Portal. No attack-path graph, no posture view, no remediation list. Changes: (1) Remove "Threat Detection" from ENGINE_ORDER. (2) Consume v2 score/label fields. (3) PDF download triggers redesigned PDF.

Change 1: Remove "Threat Detection" from ENGINE_ORDER in ReportsPage.tsx
// File: mssp_partner/src/pages/reports/ReportsPage.tsx (lines 26-32) // BEFORE: const ENGINE_ORDER = [ "Identity Hygiene", "Identity Intelligence", "Microsoft 365", "Platform Hygiene", "Threat Detection", // REMOVE THIS ]; // AFTER: const ENGINE_ORDER = [ "Identity Hygiene", "Identity Intelligence", "Microsoft 365", "Platform Hygiene", ]; // Also remove: // - THREAT_DETECTION_MAPPING constant (lines 51-57) // - The "Threat Detection" case in sanitizeEngineDetails switch (lines 75-87)

Per UW FR-P1-006: "Live Threat Detection MUST be removed from BLA scoring, engine matrix, and PDF." This is a P0/P1 change that can ship independently.

Change 2: Consume v2 riskLabel and riskScore from real API (replacing mockResolve())
// v1 behavior: map numeric riskLevel via RISK_LEVEL_TO_STR const RISK_LEVEL_TO_STR: Record<number, string> = { 1: "low", 2: "medium", 3: "high", 4: "critical" }; function mapRiskLevel(raw: unknown): string { if (typeof raw === "string") return raw.toLowerCase(); return RISK_LEVEL_TO_STR[Number(raw)] ?? "low"; } // v2 behavior: API returns riskLabel as a pre-computed string // No mapping function needed -- use riskLabel directly from response: // response.riskLabel: "Critical" | "High" | "Medium" | "Low" // response.riskScore: number (0-100, headline v2 score) // response.scoringModelVersion: "v2" (for score trend annotation)

The MSSP portal will consume the same /portal/bl/identities v2 endpoint. The riskLabel field is pre-computed server-side (eliminating the frontend mapping bug that caused the High/Critical label swap). MSSP-2 ticket: replace mockResolve() with real fetch calls.

Key changes in the "after" state: (1) Score display uses SeverityChip pattern (color + shape + text) instead of plain numeric + label. This makes severity scannable in the table. (2) Threat Detection column/engine is absent from all PDF downloads triggered from this table. (3) v2 score is displayed (may differ from v1 for some clients -- score trend chart in PDF annotates the v2 cutover date). (4) PDF download triggers the redesigned 10-page BLAMainContent.tsx (same structure as client portal PDF).

MSSP Portal Scope (Explicit Out-of-Scope Items)
  • The MSSP portal does NOT get the interactive attack-path graph. (Out of scope per UW doc.)
  • The MSSP portal does NOT get the posture view (NIST CSF / ISO 27001 / Essential Eight panels).
  • The MSSP portal does NOT get the remediation list.
  • The MSSP portal does NOT get the AD toggle. AD is reflected in the PDF if integrated, but the MSSP user cannot toggle it.
  • The score chip in the table (color + shape + text) applies the same severity encoding rules as the client portal for consistency and accessibility.
  • MSSP-2 (real API integration replacing mockResolve()) is a separate ticket with its own backend dependency. The UI changes in this wireframe can be built against mock data first and wired to the API later.
  • The Admin Dashboard is explicitly out of scope (per UW doc). No BLA changes to admin_dashboard/.
